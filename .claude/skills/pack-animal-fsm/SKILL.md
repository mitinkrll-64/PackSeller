# Конечный автомат животного

Одно животное за раз в версии 0.1. Несколько животных и отмена кнопкой — позже, но структуру данных делать так, чтобы расширение не требовало переписывания (приказ — объект, а не набор глобальных переменных).

## Состояния
```
Idle -> GoingToTrader -> Selling -> Returning -> Idle
```
Ошибочные переходы из GoingToTrader и Selling → Returning (если животное живо) или → Idle (если погибло). Из Returning ошибка (недостижима точка, таймаут) → Idle с сообщением.

## Данные приказа
- идентификатор животного и торговца (способ — из api-notes, вопрос 7: что переживает загрузку);
- точка возврата (позиция в момент нажатия «Продать»);
- время старта и таймаут из конфига (игровое время или тики — по api-notes);
- текущее состояние;
- итог для сообщения игроку (продано/сумма).

## Правила переходов
| Из | Событие | В |
|---|---|---|
| Idle | игрок нажал «Продать» (рюкзак не пуст, торговец доступен) | GoingToTrader |
| GoingToTrader | вход в зону взаимодействия | Selling |
| GoingToTrader | торговец мёртв/без сознания/недоступен | Returning |
| GoingToTrader | цель недостижима, путь заблокирован | Returning |
| GoingToTrader | таймаут | Returning |
| GoingToTrader/Selling/Returning | животное погибло или без сознания | Idle (сообщение) |
| Selling | продажа завершена или нечего продавать | Returning |
| Returning | прибытие на точку возврата | Idle |
| Returning | точка недостижима, таймаут | Idle (животное остаётся где есть, сообщение) |

## Реализация
- Автомат обновляется на тике игры из подтверждённого хука/колбэка (api-notes), не чаще заданного интервала. Никаких блокирующих ожиданий.
- Каждый переход: лог (`[PackSeller] state A -> B, reason`), единая функция смены состояния, внутри которой входные/выходные действия.
- Перед использованием любого игрового объекта на тике проверять, что он существует и валиден (объект может быть удалён вместе с клеткой мира).
- Приказ животному отдаётся через механизм из api-notes (вопрос 2). Перед этим сбросить предыдущие задачи, если это нужно и безопасно; после завершения вернуть животное в обычное поведение (на точке — стоять/следовать, как было до приказа `[TO VERIFY]`).
- Игрок может вмешаться: отдать животному другой приказ вручную. Если игра сообщает о смене задачи, автомат переходит в Idle без возврата и без сообщений об ошибке `[TO VERIFY: можно ли отследить]`. Если нельзя, фиксируется как известное ограничение.
- Время в паузе игры и при ускорении: таймаут считается в игровом времени, чтобы пауза его не расходовала `[TO VERIFY]`.

## Сохранение (этап 8)
- Состояние автомата сохраняется вместе с сейвом по образцу WorldStates из KenshiLib_Examples (api-notes, вопрос 7).
- При загрузке: если животное или торговец не найдены, приказ сбрасывается в Idle с записью в лог, без краша.
- Загрузка сейва без данных мода: автомат стартует в Idle.
- Отключение мода: сейв должен грузиться без нашего блока данных (проверка в тест-плане).
- Если нельзя сохранить состояние посреди приказа корректно, запасной вариант: при сохранении/загрузке приказ сбрасывается, животное остаётся на месте, игрок получает сообщение. Выбор варианта записать в decisions.md.

## Тесты (минимум)
Нормальный цикл; торговец убит по дороге; животное убито в пути; путь недостижим; таймаут; торговец без денег к моменту прихода; сохранение и загрузка в каждом состоянии; быстрый повторный клик «Продать»; ручной приказ животному во время выполнения.
