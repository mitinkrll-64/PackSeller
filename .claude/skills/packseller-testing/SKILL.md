# Тестирование PackSeller

Автотестов внутри игры нет. Код проверяется ревью и сборкой, поведение в игре проверяет пользователь по чек-листам, а ИИ готовит сценарии и разбирает логи. Что не проверено в игре, так и помечается.

## Файлы
- `docs/test-plan.md` — сценарии и результаты (таблица: ID, шаг, ожидание, результат, дата, версия сборки).
- Логи для анализа: `<Kenshi>/RE_Kenshi_log.txt` и отладочный лог плагина (строки с `[PackSeller]`).

## Подготовка стенда (для пользователя)
1. Новая игра или тестовый сейв рядом с городом; в отряде вьючное животное (например, бул/ботаник по правилам игры), в рюкзаке товар разных категорий.
2. Рядом несколько городов с торговцами; один город с враждебной фракцией; один кочевой торговец (должен быть исключён).
3. Включить отладочный лог плагина в конфиге.
4. Сделать резервную копию сейвов перед тестами.

## Матрица сценариев
**Окружение (этап 1):** строка плагина в логе; нет краша в главном меню и при загрузке сейва.
**Движение (этап 3):** идти к цели рядом, далеко, недостижимой; прибытие; возврат на точку; таймаут.
**Продажа (этап 4):** торговец покупает всё; частично; не покупает ничего; мало денег; нулевые деньги; пустой рюкзак; предметы с количеством больше одного.
**Список (этап 5):** кочевые не в списке; фильтр неподходящих; радиус; сортировка трёх видов; враждебный город помечен; два торговца в одном городе.
**UI (этап 6):** кнопка видна только у вьючного животного; не пропадает при пересоздании окна; окно открывается и закрывается много раз; кириллица; разные разрешения; совместимость с модом поиска в инвентаре (Organize the Inventory) и другими модами окна.
**Автомат (этап 7):** все ошибочные выходы из `pack-animal-fsm`.
**Сохранения (этап 8):** save/load в каждом состоянии; старый сейв без мода; сейв с модом, затем без мода.
**Устойчивость (этап 9):** долгая сессия, много циклов подряд, быстрые клики, смена скорости игры, паузa, смерть участников, выход в меню в середине приказа.

## Анализ логов
- Искать краш-записи, «PackSeller», предупреждения хуков, сообщения о версии KenshiLib.
- Для каждого бага: версия сборки, шаги, ожидание/факт, фрагмент лога, гипотеза, приоритет.
- Не закрывать баг без повторной проверки пользователем.

## Ревью кода (ИИ, до приёмки)
Проверять по списку:
- проверки указателей и жизни объектов; хранение указателей между кадрами;
- главный поток; нет собственных потоков;
- нет C++11 (v100);
- хуки только через KenshiLib; корректное снятие подписок и уничтожение виджетов;
- границы массивов, пустые списки, деление на ноль, переполнение сумм;
- обработка всех ошибочных выходов автомата;
- запись в лог без утечки больших данных каждый тик;
- совместимость формата сохранения: версия блока данных, обратная совместимость.

## Критерий приёмки этапа
Все сценарии этапа в `test-plan.md` выполнены, результаты записаны, найденные баги классифицированы; блокирующих нет.
