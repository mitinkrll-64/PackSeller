# Торговцы и продажа

Все обращения к игре берутся из `docs/api-notes.md`. Ниже требования к поведению, а не названия функций.

## Отбор торговцев (этап 5)
1. Из позиции животного берём радиус из конфига. Значение по умолчанию подбирается по результатам исследования; хранится в конфиге.
2. Перебираем города/поселения в радиусе и их торговцев. **Только городские торговцы**, кочевые исключены (способ различения из api-notes, вопрос 3).
3. Для каждого торговца собираем: имя, город, расстояние от животного (прямая или по пути — по возможностям API; по умолчанию прямая), деньги, фракция города и отношение к игроку.
4. **Фильтр неподходящих:** скрыть, если у торговца нет денег или он не покупает ничего из содержимого рюкзака. Выручку не считаем и не показываем, достаточно проверки «есть ли хоть один предмет, который он возьмёт и на который хватит денег» (минимальная цена из проверенного расчёта).
5. **Враждебность:** отметить город, если его фракция враждебна игроку. Поведение при враждебном городе в 0.1: показываем пометку, продажу разрешаем, но явно предупреждаем (диалог подтверждения не нужен; решение за игроком). Если отношение определить нельзя, пометка не показывается, и это записывается в decisions.md.
6. **Сортировка:** расстояние (по умолчанию), деньги, город. Стабильная сортировка, при равенстве по расстоянию.
7. Список строится при открытии окна и обновляется не чаще заданного интервала, чтобы не нагружать игру.

## Продажа (этап 4)
Программная, без имитации окна торговли.

1. **Момент:** животное вошло в зону взаимодействия торговца (как определить — из api-notes, вопрос 5).
2. **Перепроверка перед продажей** (состояние мира могло измениться за время пути): торговец жив, в сознании, на месте; животное живо; инвентарь животного доступен.
3. **Что продаём:** только предметы, которые торговец покупает и на которые хватает его денег; остальное остаётся в рюкзаке. Какие категории торговец покупает, определяется правилами игры (api-notes, вопрос 4), а не нашими догадками.
4. **Цена:** по правилам игры (множители торговца/фракции, навыки). Если игровая формула недоступна, не изобретать свою: остановиться и доложить лиду, чтобы пересмотреть дизайн.
5. **Атомарность:** либо перенос предметов + деньги проходят полностью для каждого предмета, либо предмет остаётся у животного. Порядок: проверка денег торговца → перенос предмета → списание у торговца → зачисление игроку. Деньги торговца не уходят в минус. Предметы не дублируются и не теряются.
6. **Результат:** количество проданных предметов и сумма; игроку короткое сообщение. Если не продано ничего, сообщение «Торговец ничего не купил», животное возвращается.
7. **Кому зачисляются деньги:** игроку (общий кошелёк отряда/игрока — по api-notes), не животному.
8. Все операции — в главном потоке. В отладочном логе: торговец, предметы, суммы.

## Крайние случаи
- Рюкзак пуст на момент старта: кнопка «Продать» не должна ставить приказ.
- Торговец сменился/погиб в пути: ошибочный выход конечного автомата `pack-animal-fsm`.
- Предмет экипирован или заблокирован: не продавать `[TO VERIFY]`.
- Переполнение: продавать лишь то, что влезает в расчёт денег; остаток остаётся.

## Тесты
Для каждого пункта выше в `docs/test-plan.md` есть проверка. Минимум: торговец с малым запасом денег, торговец, не покупающий категорию, пустой рюкзак, смерть торговца до прихода, продажа в враждебном городе.
