# Сборка плагина PackSeller

## Требования (из документации KenshiLib и примеров)
- Visual Studio 2019 или новее с установленным компилятором **Visual C++ 2010 (v100) x64**. Плагины KenshiLib обязаны собираться этим toolset'ом; копии VS 2010 доступны через Wayback Machine.
- Зависимости: репозиторий KenshiLib_Examples_deps (KenshiLib include + прекомпилированные библиотеки KenshiLib, Ogre, Boost и т. д.). Положить в `third_party/KenshiLib_deps/`.
- Проекту нужны: Include-каталог KenshiLib, `.lib` KenshiLib (из релиза KenshiLib), `OgreMain.lib`, MyGUI/Boost по образцу примера Kill Button.
- RE_Kenshi установлен у пользователя (версия 0.3.1+); игра запущена через него. Если в главном меню видна строка версии RE_Kenshi, он загружен.
- Известная проблема из примеров: конфигурация DEBUG может не работать, собирать Release `[TO VERIFY на момент старта]`.

## Этап 1: порядок действий
1. Попросить пользователя сообщить: версию Kenshi и магазин (Steam/GOG), версию RE_Kenshi, установлен ли VS и toolset v100, где лежит игра.
2. Создать каркас проекта по образцу Hello World из KenshiLib_Examples: структура `.vcxproj`, настройки (Platform Toolset v100, x64, Runtime Library и пр. — копировать из примера, не придумывать).
3. Минимальный плагин пишет строку в лог RE_Kenshi при загрузке.
4. Сборка → `PackSeller.dll`. Написать `RE_Kenshi.json` по образцу примера (поле со списком DLL).
5. Установка: каталог мода в `<Kenshi>/mods/PackSeller/` с DLL и `RE_Kenshi.json`, мод включить в лаунчере. **Копирование в папку игры делает только пользователь или после его явного подтверждения.**
6. Проверка: строка плагина в `<Kenshi>/RE_Kenshi_log.txt`.

## Правила кода под v100
- Без C++11: нет `auto`, `nullptr`, лямбд, range-for, `override`/`final` (в v100 есть частичные расширения MSVC — не полагаться), `std::unique_ptr`, `<thread>`, `<chrono>`, `<mutex>` стандартные. Использовать Boost из deps, если нужно.
- `NULL` вместо `nullptr`, итераторы вместо range-for, функторы вместо лямбд.
- Строки между игрой и плагином: типы из KenshiLib (`std::string` из игры, `Ogre::String` и т. п.); не смешивать аллокаторы между DLL: память, выделенную в игре, освобождать там же `[TO VERIFY]`.
- Не использовать глобальные конструкторы с побочными эффектами в игре.
- Все хуки через API KenshiLib; перед установкой хука убедиться, что подпись совпадает с заголовком.

## Диагностика
- Плагин не загрузился: проверить `RE_Kenshi_log.txt`, наличие `RE_Kenshi.json`, имя DLL, разрядность x64, toolset.
- Краш при загрузке: проверить расхождение версии KenshiLib и версии игры; пересобрать с актуальными deps.
- Все логи плагина с префиксом `[PackSeller]` и уровнем; отладочный лог управляется конфигом.
