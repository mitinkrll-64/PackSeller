# Автопродажа вьючника — дизайн-документ

Мод для Kenshi на RE_Kenshi / KenshiLib (C++ плагин). Отдельный проект, не связан с модом «Призвать наёмников».

Статус: планирование. Версия 0.1 документа.

## Идея

Игрок загружает товар в рюкзак вьючного животного. В инвентаре животного под кнопкой «OPEN BAG» (в окне животного кнопки конечностей нет, см. api-notes) появляется кнопка «Торговцы». Она открывает модальное окно со списком торговцев из ближайших городов. Для каждого торговца показаны имя, город, в котором он находится, расстояние и количество денег, и кнопка «Продать». По нажатию животное идёт к торговцу, при входе в зону взаимодействия происходит продажа, затем животное возвращается на точку, где стояло в момент нажатия.

## Решения

| Вопрос | Решение |
|---|---|
| Какие торговцы | Только городские торговцы из ближайших городов: радиус от текущей позиции животного, значение в конфиге, точное число подбирается после исследования API. Кочевые торговцы не учитываются |
| Что показываем о торговце | Имя, город, расстояние, деньги |
| Что продаётся | Только то, что торговец покупает и на что хватает его денег; остальное остаётся в рюкзаке |
| Выручка в списке | Не показываем (лишнее) |
| Точка возврата | Позиция животного в момент нажатия «Продать» |
| Продажа | Программная: расчёт цены по правилам торговца, перенос предметов, зачисление денег игроку |
| Отмена приказа кнопкой | Не в первой версии |
| Несколько животных одновременно | Не в первой версии (одно животное за раз) |
| Отношение к другим модам | Отдельный мод в отдельной папке |

## Границы версии 0.1

Входит: кнопка, окно со списком, маршрут к торговцу, продажа, возврат, русская локализация, базовая обработка ошибок, сохранение состояния приказа, а также:
- сортировка списка (по расстоянию по умолчанию, по деньгам торговца, по городу);
- скрытие неподходящих торговцев: без денег или не покупающих ничего из рюкзака (без расчёта выручки, достаточно проверки «есть ли что продать»);
- предупреждение о враждебных городах: пометка у города, фракция которого враждебна игроку `[TO VERIFY: как определить отношение фракции]`.

Не входит (версии позже): режим «другой город» (цель — город из списка городов, по прибытии поиск торговца и продажа; сначала проба: подгружаются ли торговцы вокруг животного вдали от отряда; в 0.1 список ограничен загруженной зоной ~1800 единиц), учёт цены у разных торговцев (в 0.1 множитель цены равен 1, `sell_price_mult=1.0`, без калибровки по городам и торговцам; расчёт по `getValueAll(true)`), отмена приказа кнопкой, несколько животных одновременно, выручка в списке, выбор категорий товара, повторный маршрут, автоповтор по заполнению рюкзака, избранные торговцы, обратная покупка в городе, отмена приказа при угрозе на маршруте.

## Техническая основа

- Плагин загружается RE_Kenshi, хуки ставятся только встроенной системой KenshiLib.
- Компилятор: Visual C++ 2010 (v100) x64, требование KenshiLib. Среда: Visual Studio 2019 или новее с этим toolset.
- Зависимости: KenshiLib и precompiled libs из репозитория KenshiLib_Examples_deps.
- UI: MyGUI (как в примере Kill Button).
- Сохранение состояния: по образцу примера World States Variables.
- Лицензия: KenshiLib под GPLv3, плагин тоже выпускается под GPLv3.
- Версии игры, RE_Kenshi и KenshiLib фиксируются в README.

Всё, что касается конкретных классов и функций KenshiLib, пока не проверено и помечено `[TO VERIFY]`.

## Конечный автомат

```
Ожидание -> В пути -> Продажа -> Возврат -> Ожидание
```

Ошибочные выходы (во все состояния, кроме Ожидания):
- торговец мёртв, без сознания или недоступен;
- путь заблокирован или цель недостижима;
- животное погибло или без сознания;
- таймаут (значение в конфиге);
- торговец ничего не купил: возвращаемся без продажи.

При ошибке животное возвращается на точку, игроку показывается сообщение `[TO VERIFY: способ вывода сообщений]`.

## Риски

1. Приказ «идти в точку» и отслеживание прибытия: класс и функции `[TO VERIFY]`. Проверяется первым.
2. Список торговцев из ближайших городов: как получить города и их торговцев, как определить название города для торговца, как отличить городского торговца от кочевого, как работает подгрузка мира по клеткам `[TO VERIFY]`.
3. Программная продажа: расчёт цены, какие категории торговец берёт, как списать деньги торговца `[TO VERIFY]`.
4. Добавление кнопки в окно инвентаря животного: класс окна и расположение кнопки конечностей `[TO VERIFY]`; ориентир: мод Organize the Inventory, который добавляет элементы в такие окна.
5. Опасность в пути: одинокое животное с грузом может погибнуть от бандитов или хищников. В версии 0.1 не решаем, фиксируем как известное ограничение.
6. Обновления игры ломают хуки: поэтому минимум хуков.
7. Сохранение посреди приказа: состояние должно восстановиться после загрузки `[TO VERIFY]`.

## План работ

1. Окружение: версия игры, VS с v100, KenshiLib и deps, сборка Hello World.
2. Исследование API: чтение заголовков KenshiLib, закрытие всех `[TO VERIFY]`, результат в `docs/api-notes.md`.
3. Прототип движения: идти в точку, поймать прибытие, вернуться.
4. Прототип продажи: программная продажа выбранному торговцу.
5. Список торговцев: города в радиусе, расстояние, деньги торговцев, фильтр неподходящих, отношение фракции города, сортировка.
6. UI: кнопка и окно на MyGUI, переключатель сортировки, пометка враждебных городов, локализация.
7. Конечный автомат и обработка ошибок.
8. Сохранения.
9. Тесты (чек-лист, старые сейвы), упаковка (`RE_Kenshi.json`, README с версиями).

Если этап 3 или 5 окажется неосуществимым, план пересматривается до начала работ над UI.
